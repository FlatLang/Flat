# Protected ES6 dogfood run: operator handoff

The [workflow](../.github/workflows/full-dogfood-acceptance.yml) describes a gate; it does not provide the runner, trusted files, approvals, or a passing run. If any handoff below is missing, stop. A local developer-loop pass or green PR check is not a substitute.

## Before dispatch

1. **Delivery owner:** freeze the exact commit on a remote branch or tag, review its workflow and full package source inventory, and record the commit SHA. The seed review's `source_revision` identifies the seed producer, not this delivery.
2. **Independent reviewers:** hand the operator the exact files and expected SHA-256 values specified in [Operator inputs before production dispatch](../README.md#operator-inputs-before-production-dispatch). Review the seed manifest (Node, Git, Java, bootstrap Airship JS, `flatc.jar`, `flat-es6.jar`) and its provenance receipt. Approve distinct changed and independently removable real Core sources that preserve suite entrypoints. Approve the `flat.dogfood.scaling-plan.v1` tiers, floors, ceilings, growth limits and actual BSD/GNU RSS timer path/kind/hash **before measurement**, against the source digest that fresh bootstrap must reproduce. Review supplemental evidence and its referenced files against those sources and products. Neither a hash generated by the job nor historical budgets constitute approval.
3. **Runner operator:** confirm an authorized, dedicated ephemeral POSIX runner with both `self-hosted` and `flat-dogfood` labels, Python 3.12+, reviewed seeds and timer, offline dependencies/local Git origin, and enough disk and artifact quota. Provision the following exact UTF-8 JSON object fields (no extra/duplicate keys; at most 64 KiB) on that runner. Use canonical paths without symlink aliases and lowercase 64-hex SHA-256 pins.

   | Manifest field(s) | Value to provision |
   | --- | --- |
   | `schema`, `source_revision` | `flat.dogfood.dispatch.v1`, exact delivery commit matching `GITHUB_SHA` |
   | `seed_manifest`, `review_receipt`, `review_sha256` | Absolute existing files; independent pin of the review receipt, which binds the seed manifest |
   | `changed_input`, `removed_input` | Canonical repo-relative paths to existing `.flat` files under `packages/Flat-Core/src/` |
   | `scaling_plan`, `scaling_plan_sha256` | Absolute reviewed plan file and independent pin |
   | `production_evidence`, `production_evidence_sha256` | Absolute supplemental evidence file and independent pin; include all referenced files |
   | `bootstrap_output` | New, nonexistent absolute directory with an existing canonical parent; do not precreate the output |

   Keep stage, supplemental (the evidence file's entire parent directory), and run receipt trees dedicated and disjoint, outside the checkout. Uploads include hidden files: exclude credentials and unrelated files. Obtain independent review and a pin of the **final dispatch manifest bytes**. The lost historical evidence tree is not a source of inputs.

## Dispatch and approve

Only an already-authorized operator should run these commands. Set `REPO` to the intended `OWNER/REPO`, `REF` to the reviewed remote branch/tag, `SHA` to its reviewed commit, `MANIFEST` to the absolute **runner-local** manifest path, and `PIN` to its independent digest. The two fields below are strings, not files to upload. Confirm the active GitHub account and host without printing a token.

```sh
gh auth status --active --hostname github.com
gh workflow run full-dogfood-acceptance.yml -R "$REPO" --ref "$REF" \
  -f dispatch_manifest="$MANIFEST" -f dispatch_manifest_sha256="$PIN"
gh run list -R "$REPO" --workflow full-dogfood-acceptance.yml \
  --event workflow_dispatch --commit "$SHA" --json databaseId,attempt,headSha,createdAt,url
```

Match the dispatch to its Actions URL, actor, time, SHA and attempt; do not assume the newest run is yours. **Protected environment approver:** before releasing `production-acceptance` in `flat-dogfood-acceptance`, verify the actual dispatched commit, runner provisioning, manifest pin and all local inputs against the independent handoff. Confirm the environment really enforces approval; naming it in YAML does not establish protection. If the ref moved or identity/authorization is uncertain, do not approve. Do not substitute another runner or relax permissions.

## Check the exact attempt

Set `RUN_ID` and `ATTEMPT` from the matched run. After it finishes, inspect its jobs and download its final result into a new local directory:

```sh
gh run view "$RUN_ID" -R "$REPO" --attempt "$ATTEMPT" \
  --json event,headSha,attempt,status,conclusion,jobs,url
result=$(mktemp -d)
gh run download "$RUN_ID" -R "$REPO" \
  -n "dogfood-result-$RUN_ID-$ATTEMPT" -D "$result"
cat "$result/acceptance-result.txt"
```

Require `workflow_dispatch`, the reviewed SHA, successful `receipt-tests`, `production-acceptance` and `acceptance-result`, and **`delivery_complete=true`** with `full_acceptance=true`. Cross-check `outcomes.json` in `full-dogfood-receipt-<run_id>-<attempt>`: dispatch, provisioning, bootstrap (stage0 then Java-free stage1/2), stage admission, production, plan binding, validation and producer validation must all succeed. Retain the matching `dogfood-harness-tests`, `full-dogfood-receipt`, `full-dogfood-bootstrap`, `full-dogfood-supplemental` and `dogfood-result` artifacts (each suffixed `-<run_id>-<attempt>`; workflow retention 14 days). On failure, record the URL/attempt, first failed prerequisite and available logs; a queued, skipped, missing or unknown result is not acceptance. A new attempt needs a fresh bootstrap output and, if inputs change, a newly reviewed manifest/pin.
